## 1. 一句话定义

一个浏览器扩展：在浏览器内**冒充 aria2 的 RPC 服务端**，把 aria2 的 RPC 请求**转接到浏览器自身具备的下载能力**上，让用户无需安装 aria2 本体即可使用 aria2 的大部分功能；对浏览器做不到的能力，**如实报错**而非假装支持。

## 2. 产品目标与价值主张

- **免安装**：不需要在本机安装、启动、维护 aria2 进程，装一个扩展即可。
- **协议兼容**：对外说 aria2 的 RPC 协议（JSON / XML / WebSocket），使现成的 aria2 前端（代表：AriaNg）能够接入。
- **能力诚实**：能力边界显式、可观测。做不到的功能返回错误，不做"看起来成功"的假动作。
- **可扩展的下载后端**：通过"下载引擎 + 原子能力声明"的结构，让不同的浏览器 API / 途径以统一的 RPC 表面暴露出来。

## 3. 三层概念结构

```
┌─ 第一层 用户入口层 ──────────────────────────────────────────┐
│  [转发器]                          [内置 AriaNg UI]           │
│   用户配置拦截地址（当前仅一条、      扩展打包                    │
│   精准匹配的 URL）                   必须与普通页面走同样路径    │
│   命中 → 转交 Mock 层                （扩展页注入失败时，仅允许   │
│   未命中 → 原样放行                   换"装载方式"，不换"路径"）  │
│   覆盖多途径 × 多来源                                          │
└───────────────────────────┬──────────────────────────────────┘
                            │ 请求（JSON-RPC POST/GET、XML-RPC、WebSocket）
┌───────────────────────────▼──────────────────────────────────┐
│ 第二层 Mock 层                                                │
│   对照 aria2 文档逐接口裁定：真实还原 / 伪装还原 / 不实现      │
│   把引擎结果翻译回 aria2 的语义；生成所有 RPC 响应与错误       │
│   （同一时刻只有一个引擎生效，能力集合唯一）                   │
└───────────────────────────┬──────────────────────────────────┘
                            │ 抽象后的下载任务 / 查询 / 失败结果
┌───────────────────────────▼──────────────────────────────────┐
│ 第三层 下载引擎层                                             │
│   多个内置引擎，各自静态声明原子能力（bool 标志集合）           │
│   用户同一时刻只启用其中一个；不允许用户导入引擎               │
└──────────────────────────────────────────────────────────────┘
```

## 4. 核心硬性决策

### 4.1 原始需求（用户口述的忠实记录）

**R1 目标形态**
把 aria2 的请求转接到浏览器所能具有的各种下载方式。目的是**免安装 aria2**，直接安装一个浏览器插件即可使用**大部分** aria2 的功能。

**R2 能力缺口的处理原则**
对于不支持的功能（举例：torrent 可能不支持），**应当直接报错，而非假装正常**。

**R3 接口级"三值语义"**
第二层应当**对照 aria2 文档，严格定义并处理每一个 RPC 接口**。每一个接口归入三种形式之一：

| 形式 | 含义 | 用户举的例子 |
|---|---|---|
| **真实还原** | 行为与返回都与真实 aria2 一致 | `system.listMethods`：没有 torrent 能力就**不返回**相关方法，而不是假装有 |
| **伪装还原** | 做不到 aria2 的做法，但**不报错**，返回该能力前提下**合理**的结果 | 单线程引擎收到多连接请求：不拒绝，用单线程下载并返回合理结果（第一个连接为真实连接，其余可伪造为速度 0 / 起点随意 / 全部挤在最后一块 —— 具体按语义决定） |
| **不实现** | 直接返回错误 | torrent 下载请求：直接返回错误 |

**R4 第一层（用户入口层）**
解决"无法监听端口"的问题。由两块组成：

- **R4.1 转发器**
  - 用户可以配置**要拦截转发哪些地址**（例：`localhost:6800`、`example.com:8443`）。
  - 命中配置的请求被拦截并转交给 Mock 层；**未命中的请求直接放行**。
  - 要求**尽可能多地拦截各种途径**：`fetch`、`XMLHttpRequest`、`WebSocket` 等等。
  - 要求**尽可能多地拦截各种来源**：每一个浏览器标签页、MAIN WORLD 的注入脚本等等。
- **R4.2 内置 AriaNg UI**
  - 由扩展打包一份 AriaNg 的 UI，作为**内置的用户入口**。

**R5 内置 UI 不得走特殊通道**
该 UI **不应该使用特殊方式接入 Mock 层**，而应当和正常页面一样，走同样的方式。
**唯一例外**：扩展自身页面也可能注入不进去，此时应当做**最小修改**——只在这个页面中，**用另一种方式加载那个转发器**，而不是改用别的接入方式。

**R6 第二层（Mock 层）**
负责**还原且真实地**处理转发器发来的请求，转接到下载引擎，然后返回结果。对照 aria2 文档，**严格定义、处理每一个** JSON / XML / WebSocket… 的 RPC 接口，每个接口按 R3 的三值语义裁定。

**R7 第三层（下载引擎层）**
- 下载引擎**可以声明自己的能力**。
- **可以有多个下载引擎**。"多个引擎"的含义是：**使用不同的浏览器 API 或途径，实现的能力范围不同的下载方式**。
- **不需要允许用户自己导入引擎**，只有代码内置的下载引擎。
- 可以从**最基础的下载引擎**开始实现。

### 4.2 由推导确认的边界

**R8（原 D1）服务对象边界**
浏览器扩展**无法监听 TCP 端口**。能被服务的客户端只有：**运行在浏览器内、通过 JS API（fetch / XHR / WebSocket）访问 RPC 地址的代码** —— 包括普通页面、扩展页面、内置 AriaNg UI。
**非目标**：桌面软件、命令行 `curl`、浏览器地址栏直接访问、浏览器之外的任何脚本。

**R9（原 D2）拦截层次**
拦截发生在 **JS API 层**——在请求**发出之前**就地短路，**不是**网络层的重定向 / 代理。
- 命中规则后请求**根本不会发到网络上** ⇒ CORS、混合内容、证书、真实服务是否存在**全部不适用**。
- 与"用 DNR 重定向"不是同一条路：DNR 走网络层，拿不到"返回任意响应体"的能力。

**R10（原 D3）"伪装还原"的判据**
**判据是"最终结果是否兑现"，不是"过程是否一致"。**
- **假装正常（R2 禁止）** = 请求被接受、返回成功，但用户**最终拿不到期待的结果**。
- **伪装还原（R3 允许）** = **真实结果会发生**（文件真的被下载下来），只是**中间过程 / 字段细节与 aria2 不完全一致**。
→ 这是 Mock 层所有三值裁定的**唯一裁决标准**。

**R11（原 Q-C1）引擎声明原子能力**
引擎只声明自己具备哪些**原子能力**，**不声明"支持哪些 RPC 方法"**。用户给的示例能力名：`multithread`、`withHeader`、`memUnlimited`。

**R12（原 Q-C2）多引擎：同时只启用一个**
多引擎的用途是**让用户自己选**。当前阶段：**用户选哪个就启用哪个，全局只能启用一个**。多引擎并存 / 路由 / 降级**本轮不做**。
→ 原"按优先级路由"方案**作废**；Mock 层不需要处理多引擎能力合并。

### 5.2 需要展开的裁定详情

**Q-B2 错误形态三段式（已生效）**

1. 引擎/能力不支持的方法 → **不出现在** `system.listMethods` 中；
2. 调用它 → JSON-RPC 协议级错误 **`-32601 Method not found`**；
3. 方法存在但**本次请求的场景**不支持 → 返回 aria2 风格 `{"code":N,"message":"..."}`，且 **N 优先使用 aria2 原生 errorCode**，无对应时再自行定义。

**Q-B3 伪装自洽性（已生效）**

伪装的字段**必须**满足 aria2 的内部不变量 ⇒ 需要一个"伪装数据与真实进度对齐"的机制。已识别的相关不变量（详细设计阶段补全）：

- `sum(files[].completedLength) == completedLength`
- `connections` 中各分片不重叠，且并为文件分片的划分
- `downloadSpeed` 与 `completedLength` 的增量大致自洽（前端会自行计算总速度与 ETA）
- 状态迁移合法：`waiting → active → complete / error / removed`，`paused` 可从 `active`/`waiting` 进入

**Q-B4 判定粒度（已生效）**

- 判定绑定在 **"方法 + 请求上下文"** 上；方法级只是这张表的**投影**，供 `system.listMethods` 使用：某方法只要在**任一**上下文下不是"不实现"就保留，全上下文都不支持才隐藏。
- 这张表**不手工逐行枚举**，而是由规则推导：
  ```
  引擎原子能力集合  +  请求上下文（参数分类）  →  接口行为（真实 / 伪装 / 不实现）
  ```
- **合成规则：一票否决** —— 一次请求同时命中多条规则时，只要有一处判"不实现"，整体即为"不实现"；否则取最弱的正向结果（真实 > 伪装）。
- 用户指示：**这张表之后由用户发起、以文档形式定义清楚**；现阶段**不考虑代码实现**。

**Q-B5 运行期错误（已生效）**

"条件性可用"不单列为第四种语义，归入**运行期错误**。它有两个来源：
- **引擎报告**：权限未授予、需要用户手势、API 在当前上下文不可用等 —— 引擎返回**自定义的失败结果**（非 aria2 错误，形态见 Q-C4）。
- **Mock 层自查**：例如无引擎启用（等同零能力引擎，见 Q-C6）、能力缺失（走 R3 的"不实现"）。

**Q-B6 版本号语义（已生效）**

`getVersion` **不作能力协商开关**；返回的版本号 = **实现时对标的 aria2 版本 + 一个后缀**。
→ 后果：前端会按真实版本号展示全部功能按钮（含我们不支持的 BT 等），用户点击后收到 R2 的错误。**这是预期行为**（见 §6）。

**Q-B7 进度姿态（已生效）**

选定 **b**：只在开始 / 结束两个瞬间改变状态。
补充理解（待用户确认）：**b 适用于"引擎确实拿不到进度"的情形**；若引擎能通过句柄主动轮询取得真实进度（例如 `chrome.downloads` 在开始回调拿到 `DownloadItem` 句柄后主动查询 `bytesReceived` / `totalBytes`），则**按真实进度上报，不伪造曲线**。

**Q-B8 能力模型（已生效）**

- 能力集合 = **一个固定 enum 上的 bool 标志集合**。每个能力只有"有 / 无"两态。
- **不存在数值型能力**（例如不表达"最大 1GB"）。若将来需要表达上限，只能新增一个离散能力名（如 `memUpTo1GB`）——这是布尔模型的已知代价。
- **"能力缺失时该伪装还是该拒绝"由 Mock 层按能力类别统一规定**，引擎只陈述事实、不碰 aria2 协议（与 R7、R11 一致）。

**Q-C4 运行期失败的错误形态（已生效）**

引擎能力是**静态**的。用户未授权等运行时情形**不缩小能力**，而是**报错**：不是 aria2 错误，而是**类似网络错误的自定义状态码 + 信息**（具体语义待定）。
→ 与 Q-B5 呼应，构成"引擎侧错误模型"。

**Q-C5 引擎切换（已生效）**

**有活动任务时禁止切换启用引擎。**

**Q-C6 无引擎状态（已生效）**

首次安装时**启用一个默认引擎**。若真的一个引擎都没启用，**等同于启用了一个零能力引擎**（所有下载类方法判"不实现"；非下载类接口的真实还原行为待定）。

**Q-D3 WebSocket 实现方式（已生效）**

第一版就实现 WebSocket 通道。允许的实现方式是：**转发器轮询 Mock 层**，从而在页面上近似出"Mock 层主动推送"的效果（不依赖 SW 的生命周期）。

**Q-D5 持久化（已生效）**

- 只在**浏览器彻底退出**后才模拟 aria2 重启。
- **SW 重启不构成重启**（因为浏览器没退出）⇒ Mock 的状态、任务列表必须**持久化在扩展存储**中，**不得依赖 SW 内存**。
- 这与 R12 / Q-C5 结合，意味着"当前启用的引擎"也必须是持久状态。

## 6. 已接受的风险与预期行为（**不是 bug**）

以下都是裁定的直接后果，记录在此以免后续被误判为缺陷。

1. **前端会显示不可用的功能按钮**。因 Q-B6 不做版本协商，AriaNg 等前端会按对标的 aria2 版本展示全部功能（含 BT 等）。点击后收到 R2 的错误响应。
2. **命中拦截地址后，该地址上的真实服务无法再被访问**（R9 + Q-A3）。用户配置即放弃该地址的真实连通性。
3. **无来源白名单 + 可关闭的 rpc secret 意味着：任何能命中该 URL 的页面都能完全控制下载**（创建 / 删除 / 查看任务）。真实 aria2 在不设 secret 时也是这个表现，属于**自觉接受**。风险面当前被 Q-D1（只支持一条精准匹配的 URL）限定。
4. **拦截存在盲区**（Q-D2）：`chrome://` 页面、扩展页 CSP、PDF viewer、view-source、`document_start` 之前已发出的请求、不经标准 JS API 的网络途径、以及技术上拦不到的 Worker 内请求。**必须明确列出并告知用户**。
5. **能力模型是纯布尔的**（Q-B8）：无法表达阈值类能力，只能靠新增离散能力名近似。
6. **同一时刻只能启用一个引擎**（R12），切换时若有活动任务则被禁止（Q-C5）。
